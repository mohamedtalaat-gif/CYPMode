# Use and citation

This page says how to cite CYPMode, what counts as using it, and what the author asks of anyone who reuses it. The rights and the duties are those of the licence files in the root of the repository (`LICENSE*`, `NOTICE`);
this page does not replace them. It adds the form of the citation, and it states plainly what a licence can and cannot do.

[`CITATION.cff`](CITATION.cff), which is also what GitHub reads for its "Cite this repository" button.

## How to cite

Cite the archived release, with its DOI once `CITATION.cff` lists one (the DOI of the software record on Zenodo; the version of the record that was made after the challenge closed holds the full set of results, figures
and the notebook). Until a DOI is listed, cite the repository and the commit that you used. A ready entry:

```bibtex
@software{talaat_cypmode,
  author  = {Talaat, Muhammad},
  title   = {CYPMode: time-dependent CYP inhibition and CYP3A4 structure prediction for the OpenADMET CYP blind challenge},
  year    = {2026},
  url     = {https://github.com/mohamedtalaat-gif/CYPMode},
  note    = {Cite the DOI listed in CITATION.cff when there is one}
}
```

The method report ([`METHOD_REPORT.md`](METHOD_REPORT.md)) is the description of the method and of its evidence; cite it together with the software when the method, and not only the code, is what you use. The data that
this code generated and that were deposited in a separate record have a DOI of their own, listed in `CITATION.cff`; cite it when you use the data.

## What counts as use

- **Code.** Running it, copying a function, a module or a script into another work, or building on it. Keep the copyright notice and the `NOTICE` file, as the licence says, and cite the software.
- **Data generated by the code.** Every directory of predictions, caches and outputs that a script of the repository creates carries a `PROVENANCE.json` (and a file such as a feature table carries `<name>.provenance.json`
  beside it) that names the author, the repository, the licence, the text to cite, the commit and the date of the run; the scripts print the same notice when they start. Data that you regenerate with this code carry the
  same record, and the record is part of what the licence asks you to keep. Data in the deposited record are cited by their DOI.
- **Figures, the film, the card and the notebook.** They are documents, and the licence of documents applies: credit the author and say whether you changed them.
- **Ideas.** The label rule recovered from the data, the contamination fix of the CYP3A4 pool, the scoring-set-aware yardstick, the selection-aware CYP2D6 model, the margin rule and the relaxation gate are described in the
  method report. A work that reports one of them should cite the method report.
- **Third-party components.** The programs, models and data that CYPMode uses keep their own licences and have their own citations (Appendix C of the notebook, section 14 of the method report). Citing CYPMode does
  not cite them.

## What a licence can and cannot do

A licence is a permission with conditions. It can require that the notice and the attribution stay with the work, and that changes are marked; it cannot make anyone read this page, and a program cannot enforce it: nothing in
this repository refuses to run, because a program that refuses is not open source. The record in the generated data is there so that the origin of a file can always be found, and so that a use without attribution is
recognisable as one. Anyone who wants to use the work in a way that the licence does not permit should ask the author.
