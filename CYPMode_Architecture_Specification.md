# CYPMode: Architecture Specification (v1)

The single reference for CYPMode's architecture, covering both the TDI
track (this document's original scope) and the Structure Prediction
track (see the "Official challenge update" section below for how that
track entered the project) — one project, one name, with each track's
own inputs/outputs kept in their own separate, clearly organized
folders (`data/tdi_track/outputs/` for TDI, `data/structure_track/inputs/` and
`data/structure_track/outputs/structure_track_results.json` for structure
prediction), not merged together. This document supersedes the various
diagrams sketched earlier in planning discussion. See
`CYPMode_DATA_AUDIT.md` for the evidence each TDI-track decision below
is based on — this document states the conclusions, that one has the
numbers.

## Official challenge update (2026-09-25, halfway-point blog post)

Real, official information from OpenADMET's own "Halfway Through the
OpenADMET CYP Challenge" post and Discord, directly relevant to how this
project's own results should be interpreted and prioritized:

- **Interim leaderboard released, full test set (not the half-set live leaderboard).** Uses a Benjamini-Hochberg procedure to group statistically-indistinguishable submissions into tiers — the same real-world validation of this project's own move toward Tukey HSD-corrected significance testing (see Combined-feature stacking section below), not a coincidence noticed after the fact.
- **TDI track: 26 real teams statistically tied in Tier 1**, spanning a real MCC range of 0.341 (aries) to 0.398 (nova). **The real, actionable target is MCC ≥ ~0.34, not "beat every point below us"** — our own current best validated single-isoform numbers (CYP3A4 ~0.375 tuned, CYP2D6 ~0.09) give a concrete gap to close, especially for CYP2D6.
- **Official, precise explanation for CYP2D6 being the harder isoform, beyond the earlier assay-noise finding**: the test set's hit-expansion construction prioritized CYP3A4/CYP1A2/CYP2C9's top hits, not CYP2D6's — so CYP2D6's test compounds are inherently less potent than the other three isoforms, a real train/test distribution shift specific to CYP2D6, not just measurement noise.
- **A new Structure Track launched today**, running alongside TDI/Direct-Inhibition through November 3, 2026: 20 new real cryo-EM CYP3A4 structures (15 from the training set, 2 from the test set, 3 additional), scored primarily by LDDT-PLI (secondary: BiSyRMSD) via the OpenStructure pipeline. **PoseBusters is now an official, mandatory part of scoring**: any submitted structure that fails PoseBusters' physical/chemical sanity checks scores LDDT-PLI=0 regardless of geometric accuracy otherwise. This directly elevated this project's own PoseBusters installation from a nice-to-have validity gate to something worth prioritizing for real.

**Resolved**: checked directly by cross-referencing `data/structure_track/inputs/structure_track_test_blinded.csv` (the real official 20-compound set) against every real prediction directory in `data/structure_track/outputs/out/` (78 total, across four real sources: the 20 official compounds, 50 separate Tier 3 compounds selected for TDI feature engineering by OOF uncertainty — not the same population, only 1 compound overlaps — the 4-compound TDI reference panel, and 5 other named reference drugs). **All 20 official Structure Track compounds are present and accounted for** — this project's local batch already matches the official set, no reconciliation needed.

**Real PoseBusters batch result, run immediately on every real completed structure this project has** (`cypmode.validation.pose_validity`; real, current count as of the last run — see `docs/figures/structure_track/` for the up-to-date figure, this number moves as more structures complete): **46/57 (80.7%) pass every check.** 11 fail: 10 on the identical check, `minimum_distance_to_protein` (a real steric clash, not a borderline rounding case — confirmed on itraconazole specifically: smallest ligand-protein distance 2.42 Å, 74.4% of the safe VDW-sum threshold, one real clashing atom pair), and 1 (`OCNT-2311782`) on an RDKit valence-parsing error during ligand reconstruction, a separate problem from pose validity itself. This is a real, direct confirmation of exactly the failure mode OpenADMET's own blog post warned about ("co-folding algorithms often optimize for raw atom placement at the expense of physical plausibility") — caught locally, before any submission, which is the entire point of running this now rather than after a real LDDT-PLI=0 on a real submission. Not yet remedied (e.g. via local clash-relief minimization or re-prediction with different settings) — a real, concrete pre-submission checklist item.

## Official challenge rules and scoring detail (from OpenADMET's own HF Space FAQ)

Real, official rules and scoring mechanics not previously documented here:

- **The real full isoform panel**: Direct Inhibition (regression) is scored across FOUR isoforms — CYP3A4, CYP2C9, CYP2D6, CYP1A2. TDI (this project's own track) is scored on CYP3A4 and CYP2D6 only, as already assumed throughout this project.
- **Two independent tracks, two independent leaderboards.** Direct Inhibition (regression) and TDI (classification) are submitted as separate files and ranked completely independently — a team can enter either or both. The Structure Track (launched later, see above) isn't mentioned in this FAQ, but given it's scored on LDDT-PLI/BiSyRMSD/PoseBusters — metrics that can't sensibly merge with MCC or MA-ST-RAE into one number — it's almost certainly also independently ranked, though that specific point isn't confirmed in writing anywhere this project has seen yet.
- **Real test set size: 750 compounds**, single continuous stage (not two sequential unblinding phases like some prior OpenADMET challenges) — an interim leaderboard at the halfway mark (already covered above), full ground truth withheld until the challenge closes.
- **Direct Inhibition's real primary metric**: Macro-Averaged Soft-Threshold Relative Absolute Error (MA-ST-RAE). Predictions falling inside the credible interval of the fitted dose-response curve incur zero penalty — a deliberate design so models aren't punished for missing noisy point estimates on low-activity compounds (pIC50 < 4, below the assay's reliable dynamic range). Not directly relevant to this project's own TDI-only scope, but useful context for how the organizers treat assay-noise regions generally.
- **The real, precise TDI positive/negative labeling rule** (this project's own training data already carries these as the pre-computed `{cyp}_is_TDI` columns, so this is confirmation of what's already being used, not a change): a compound is **positive** if its direct-inhibition pIC50 is above 4 (the assay's reliable floor) and the TDI-arm shift exceeds 2-fold (log10(2) = 0.301); **negative** if pIC50 is above 4 but the shift doesn't clear 2-fold; **inferred positive** if direct-inhibition pIC50 is below 4 (too low to measure a shift directly) but the TDI-arm pIC50 itself clears 4.301 (mathematically guarantees a >2-fold shift); **assigned negative** if both arms are below 4 (TDI can't be determined, but compounds this inactive in both arms are labeled negative by convention, on the reasoning that they wouldn't be prioritized for follow-up kinetic study anyway). Scored positive class = positive + inferred positive; scored negative class = negative + assigned negative.
- **Proprietary-data disclosure**: submitters must check an "I used proprietary data" box, publicly shown on the leaderboard. CYPMode uses only public data (PubChem, BindingDB, TDC) — this box would be unchecked for an eventual submission.
- **Open-sourcing code is encouraged, not mandatory** for standard ranking, but required to be eligible for the separate **"Innovation in ML Award"** (architectural novelty, creative data usage, novel uncertainty quantification, clever engineering — independent of leaderboard rank) and for community kudos. Worth keeping in mind: CYPMode's real, rigorous statistical-significance discipline and diverse external-data integration (this document's own honest record of negative results included) is exactly the kind of "creative data usage / clever engineering" this award looks for, separate from raw MCC rank.
- **Submissions rate-limited to once per 12 hours**; only the latest valid submission counts. Final deadline **November 3, 2026, 23:59 UTC** (matches the Structure Track's own deadline already documented above).
- **No summary preprint planned** — OpenADMET publishes blog posts and Zenodo technical reports instead (matching the citation pattern already used for the ExpansionRx retrospective below, which itself is one of these).

## Lessons from the OpenADMET-ExpansionRx blind challenge (Castellanos et al. 2026)

A separate, already-completed OpenADMET community blind challenge (nine ADMET
endpoints — LogD, kinetic solubility, microsomal clearance, Caco-2
permeability, protein/tissue binding — on a 7,608-compound proprietary
dataset from Expansion Therapeutics, Sept 2025–Jan 2026) was written up by
the same organizing team as our CYP challenge, including Pat Walters as
corresponding author. It is not the CYP challenge itself, but several of
its findings are directly relevant to this project's own methodology and
are worth recording honestly, positive and negative alike:

- **Real, independent confirmation of the CYP challenge's own statistical methodology.** The organizers found and fixed a genuine "pseudoreplication" bug in their first-pass significance testing: applying Tukey HSD directly to bootstrap-resampled metric distributions inflates apparent significance, because bootstrap resampling of a *fixed* set of precomputed predictions isn't the same as the independent, distinctly-retrained replicates (e.g. 5×5 nested CV with different seeds/folds) that a Tukey/ANOVA test actually assumes — treating `B` bootstrap iterations as independent samples lets `MS_Error/n → 0` and produces artificial p-value collapse. Their fix — paired bootstrap-difference distributions with Holm-Bonferroni/Benjamini-Hochberg correction — is stated explicitly to apply to "current and future challenges, such as the OpenADMET PXR and CYP blind challenges," confirming this is the real methodology behind our own challenge's Benjamini-Hochberg tiering (see above). Separately, this also confirms `cypmode.challenge.stacking_significance`'s own approach is on the methodologically correct side of this exact debate: it uses genuine repeated 5×5 CV with independent retraining per fold/seed (the "Ash et al." protocol the paper cites as valid), not bootstrap resampling of a fixed prediction set — the failure mode the organizers found and fixed doesn't apply to how this project tests its own feature-stacking claims.
- **Real, honest caution about classical ML's ceiling.** Among the top 20 ExpansionRx entries, 2D graph neural networks (mostly Chemprop) and chemical foundation-model pretraining (CheMeleon) dominated; models relying purely on classical ML (LightGBM/XGBoost/CatBoost on descriptors/fingerprints — CYPMode's own current approach) ranked no higher than #46. This isn't proof the same holds for CYP TDI classification (different task: binary classification on ~6,100 compounds vs. 9 continuous endpoints on ~7,600 compounds from a denser, real optimization-campaign chemical series), but it's a real, relevant signal worth taking seriously rather than dismissing, especially if CYPMode's MCC plateaus well below Tier 1 after the current feature-engineering avenues are exhausted.
- **Validates two choices already made here.** (1) External public data was strongly associated with top-tier performance (16 of the top 20 entries used it) — the same direction as this project's own PubChem/BindingDB auxiliary-feature work. (2) Hyperparameter optimization was *not* a major performance driver for top teams ("data engineering and feature augmentation mattered more than architecture-level tuning") — consistent with how this project has spent its own effort so far.
- **A real, generic blind spot worth remembering when interpreting any result here**: both the GNN/foundation-model and classical-ML/fingerprint approaches essentially failed to predict property differences between stereoisomers — predicted differences collapsed to near-zero even where real measured differences were large (median predicted difference ~0.005–0.007 log units for enantiomers whose real median difference was 0.056, and even worse relative to diastereomers' larger real differences). Two-dimensional/topological features and even most 3D representations carry little to no stereochemical signal by construction. CYPMode's own Morgan-fingerprint + RDKit-descriptor stack almost certainly shares this exact blind spot; no fix is proposed here, just an honest acknowledgment for anyone reading a CYPMode prediction on a stereoisomer pair.
- **"Knowing when a model applies is still harder than making it accurate"** (the paper's own words) — no applicability-domain signal they tried, including a trained error model, exceeded Spearman ρ ≈ 0.6 with real error. Relevant context for how much confidence to place in `cypmode/challenge/reliability.py`'s own OOD/applicability-domain score: a real, useful signal, but not one to over-trust as a precise reliability guarantee.

Citation: Castellanos, M. A. et al. *Assessing the state of the art in
ADMET prediction: Lessons from the OpenADMET-ExpansionRx community blind
challenge.* ChemRxiv, 2026-09-23. https://doi.org/10.26434/chemrxiv.15009342.v1
(preprint, not yet peer-reviewed, CC BY 4.0).

## Real, sobering evidence on Boltz-2/OpenFold3 ligand-placement accuracy for CYP3A4 (Huddleston, OpenADMET blog, 2026-06-02)

A real, official OpenADMET blog post — "Cofolding? I hardly know her! -
Cofolding Methods on ADMET Targets," Part 1 of a series, DOI
10.5281/zenodo.21785463 — directly evaluated **Boltz-2 and OpenFold3**
(this project's own two structure-prediction tools) against **real PDB
structures for CYP3A4 and PXR**, using the oracle-ranking protocol (best
of 5 samples per structure, selected against real ground truth — an
optimistic upper bound, not what a real blind submission gets to do).
The real, quantified result is sobering and directly relevant to this
project's own Structure Track work:

- **Ligand placement succeeds (BiSyRMSD < 2Å) only 57.8% of the time for Boltz-2 on CYP3A4, and only 31.5% of the time for OpenFold3** — despite backbone (Cα) RMSD staying under 0.75Å in every case. Getting the protein fold right is not remotely sufficient for getting the ligand pose right. (PXR was similar or worse: 38.5% / 32.7%.) A well-studied control target, p38 kinase, scored high on all metrics for both tools — confirming the CYP3A4/PXR failures are real, target-specific gaps, not a general tool malfunction.
- **This is not simply a training-data-coverage problem.** 78.9% of the tested CYP3A4 structures were already inside Boltz-2's own training set (cutoff June 2023) — and performance was statistically the same whether a structure was in-training or held out. The models are not learning real CYP3A4 ligand chemistry even from structures they were trained on directly.
- **A specific, real CYP3A4 failure mode, worth remembering for any of this project's own predictions**: the heme consistently anchors correctly (the models place it right essentially every time), but ligand *orientation* relative to the heme is still frequently wrong even so — and the most extreme failures (BiSyRMSD > 10Å) are consistently cases where a real *allosteric*-site ligand (e.g. progesterone) gets placed in the *orthosteric* (heme-proximal) pocket instead. If any of this project's own real Structure Track compounds are known or suspected allosteric binders, this is a concrete, named failure mode to check for specifically, not a generic caveat.
- **Real, direct warning about confidence-based model selection**: "the confidence and ranking scores output by these methods offer no useful signal... show no meaningful correlation with BiSyRMSD, and rarely rank the best predicted structure first." This is a genuine caveat for `cypmode.validation.pose_validity.select_valid_model`, which tries `model_0`, `model_1`, ... in Boltz-2's own confidence-ranked order until one passes PoseBusters: passing PoseBusters (physical/chemical plausibility) is a real, useful, different bar than being geometrically *correct* relative to a true structure, and this post's own finding is that confidence ranking doesn't reliably surface the geometrically-correct sample even when one exists among the 5. A structure that passes PoseBusters is not thereby confirmed accurate — this project's own real PoseBusters pass rate (80.7% as of the last run) should not be read as "80.7% of our poses are correct."
- **Independent, real confirmation that this project's own BiSyRMSD approximation (`cypmode.validation.bisy_rmsd`) uses the right real definition**: the post's own stated method — "Ligand RMSD after binding site superposition, corrected for molecular symmetry" — is exactly the Kabsch-pocket-superposition-then-symmetry-aware-RMSD approach already built and tested here, independently arrived at before finding this post.

**Real, honest implication for this project**: Boltz-2 (already in use) is the *better* of the two real open options for CYP3A4 specifically (57.8% vs. OpenFold3's 31.5%), which is a point in favor of the existing pipeline choice, not a reason to switch to OpenFold3 as a straight replacement — OpenFold3-preview's own real value here is likely as a second, independent cross-check on a prediction (given the two models' errors aren't obviously the same failure mode), not a drop-in upgrade. Given confidence scores are shown to carry no real signal, this project's own PoseBusters gate remains the right kind of check to keep running (it catches real, physically-impossible structures), but should not be treated as a proxy for pose *correctness* — a real, separate concern this project doesn't yet have a way to check locally without a true reference structure.

Citation: Huddleston, K. "Cofolding? I hardly know her! - Cofolding
Methods on ADMET Targets." *OpenADMET Blog*, 2026-06-02.
https://doi.org/10.5281/zenodo.21785463

## Component-by-component

**Tier 1 — universal chemical representation.** Morgan fingerprints (ECFP4, radius 2, 2048 bits) + RDKit descriptors. Computed for every compound, train and test. No missingness.

**Tier 2 — CYPMode mechanistic evidence.** Motif flag only (`cypmode.metrics.motifs`). The trialkylamine flag (`cypmode.metrics.amines`) was tested and dropped — it actively hurt CYP2D6 MCC and did nothing for CYP3A4 in a real multivariate model (M0–M3 ablation). The underlying chemistry (verapamil/diltiazem/troleandomycin's real trialkylamine-mediated TDI) is still real; the specific feature engineering (a standalone binary flag) is what failed at scale.

**Tier 3 — structural augmentation, CYP3A4 only.** Boltz-2 + explicit heme + covalent axial-cysteine bond (`cypmode.validation.pipeline`), run only on a **fixed budget of 50 compounds** (`cypmode.challenge.tier3_selection.select_fixed_budget_oof`), ranked by out-of-fold classification uncertainty across the whole labeled population. **Not built for CYP2D6**, deliberately: this project has no validated CYP2D6 structural pipeline, and inventing one to force architectural symmetry would be a real research project on its own, not something to improvise under this timeline. CYP2D6's head simply has no structural branch.

**Selection mask — revised from the original "motif OR uncertain" spec.** Checked against the real data first: motif-positive alone covers ~42% of the labeled CYP3A4 population, so the original OR-clause selected 46–72% of ~3,584 compounds regardless of quantile — thousands of compounds against a real observed Boltz-2 cost of 15–30+ minutes each, not tractable. Motif is already a free Tier 2 feature, so spending Boltz-2 on a motif-positive compound the model already "knows about" adds nothing. Revised policy: pure OOF-uncertainty ranking, no motif clause, hard fixed budget (N=50) sized to the real compute budget rather than an open-ended fraction of the dataset. The threshold/ranking model is trained fold-internally (never sees the fold it scores) — see `cypmode/challenge/tier3_selection.py` and its leakage tests.

**OOF Direct-Inhibition Bridge.** A separate regression model (`cypmode.challenge.oof_bridge`), predicting direct-inhibition pIC50 with out-of-fold predictions (trained on the training fold, applied to the held-out fold) to avoid leaking the TDI model's own validation labels through potency information. **Revised from the original Tobit/censored-regression plan**: checked the real data first and found no hard censoring at the pIC50=4 floor (values continue smoothly down to ~1.9, no pile-up) — what's real is heteroscedastic measurement noise, with the reported std column jumping 5–10x below pIC50=4. Tobit assumes the wrong generating process for this data; inverse-variance weighted regression (using the real, measured std per compound) is used instead. Feeds into Feature/Evidence Fusion as a parallel input stream alongside Tier 1/2/3 — not a step applied after them. Real result: CYP3A4 OOF MAE 0.730, CYP2D6 OOF MAE 0.645 (pIC50 spans ~6 log units).

**Shared Trunk.** Treated as a hypothesis to test, not an assumed design. A small, plain-PyTorch shared-trunk MLP (`cypmode.challenge.multitask` — one trunk, one head per isoform, masked BCE loss so a compound missing one isoform's label contributes no gradient to that head) was built instead of installing `openadmet-models`, whose real dependencies (PyTorch, Lightning, ChemProp+CheMeleon, CatBoost, XGBoost, TabPFN) exist only in a separate conda env with no pip-installable `pyproject.toml`.

**Full real comparison, same 5-fold CV protocol, same feature set (descriptors + motif + Morgan) throughout:**

| Model | CYP3A4 MCC | CYP2D6 MCC |
|---|---|---|
| M3, independent heads, 0.5 threshold | 0.300 | 0.043 |
| M3, independent heads, tuned threshold | **0.375** | 0.078 |
| Shared trunk, 0.5 threshold | 0.250 | 0.099 |
| Shared trunk, tuned threshold | 0.266 | **0.113** |

Threshold tuning helps both architectures, but helps the independent-head model more (CYP3A4 +0.075, CYP2D6 +0.035) than the shared trunk (CYP3A4 +0.028, CYP2D6 +0.014) — the gap between the two architectures narrows slightly for CYP3A4 but never closes. **The split is consistent and real, not fold noise from a single run**: independent heads are clearly ahead for CYP3A4 in every variant tested; the shared trunk is clearly ahead for CYP2D6 in every variant tested. Neither architecture dominates the other.

**Decision: per-isoform model choice for the final assembled model, not one global architecture.** CYP3A4 uses the tuned independent-head model (0.375); CYP2D6 uses the tuned shared trunk (0.113). This is a real, evidence-based asymmetry — CYP2D6's weak baseline signal (MCC≈0.05 from the very first baseline) benefits from whatever cross-isoform regularization the shared trunk provides, while CYP3A4 already has enough of its own signal that sharing a trunk with a noisier label dilutes it. Not treated as final until Tier 3's structural features are wired in for CYP3A4, which could change its calculus again.

**Reliability score.** Cross-cutting, computed from ensemble disagreement + Tanimoto-to-training-set distance + Boltz-2's own confidence score where Tier 3 ran. Deliberately kept outside the prediction path. Not called "uncertainty quantification" in any deliverable until its correlation with real held-out prediction error is measured and reported.

**Stratified evaluation by chemical familiarity.** In addition to overall MCC, validation compounds get split by Tanimoto similarity to the training set (familiar vs. OOD-like), to test the specific, falsifiable claim that structural/mechanistic augmentation helps disproportionately on compounds the 2D model is already uncertain about — a stronger scientific result than an aggregate MCC delta, and the basis of the Innovation Award pitch.

**Split-validity diagnostic** (`cypmode.challenge.split_validity`). A CV split can look far more reliable than it is if the validation compounds are chemically close to training (near-duplicates/analogs) rather than a genuine test of generalization — a known, general risk in cheminformatics benchmarking, not something specific to this challenge. Checked on our own real data: **our own i.i.d. CV folds are, if anything, chemically less similar to their own training portion (median similarity 0.448, 38.3% ≥0.5) than the real 750-compound blinded TDI test set is to our full training set (median 0.569, 81.5% ≥0.5)**. A mildly reassuring sign (not a guarantee) that our CV-measured MCC is unlikely to collapse on the blind set the way it could if the blind set were instead the more chemically-novel side of that comparison. **Since confirmed with a real mechanistic explanation, not just an observed number**: the challenge's own public documentation (`config.py`'s `ABOUT_MD` on the official HF Space) states the blind test set was built by "hit expansion... purchasing the top 10 chemisimilars (ECFP4 Tanimoto similarity) per hit compound" from the training population's own top hits (CYP1A2/CYP2C9/CYP3A4 hits specifically). Our similarity finding isn't a coincidence — it's a direct, documented consequence of how the test set was constructed. Reported honestly as a diagnostic with a now-confirmed mechanism, still not proof of transfer.

**Official scoring harness — verified as far as publicly possible.** The actual metric-computation code runs in a private AWS Lambda (`backend/lambda_handler.py`, referenced but not included in the public HF Space repo) — not independently auditable. What the public repo *does* confirm directly (`config.py`, `submission.py`): the TDI track's primary metric is plain Matthews Correlation Coefficient (no custom variant), macro-averaged (unweighted mean) across exactly `CYP2D6_is_TDI` and `CYP3A4_is_TDI`; the required submission schema (`SMILES`, `Molecule_Name`, `CYP2D6_is_TDI`, `CYP3A4_is_TDI`, 750 rows, no NaN, boolean values) matches `cypmode.challenge.submission`'s validator exactly; and the positive/negative/inferred-positive/assigned-negative label rule (direct-inhibition pIC50 vs. 4, TDI-arm shift vs. log10(2)=0.301) matches `cypmode.validation.tdi_reference.TDI_SHIFT_LOG2_THRESHOLD` exactly. One previously-unknown, real detail: **not every compound's prediction is actually scored** — "only compounds whose label can be assigned with confidence contribute to the score," per the official FAQ. Also newly confirmed: CYP2D6 uses a *different, label-free mass-spectrometry assay* (not the fluorescence-based kit used for the other three isoforms) specifically because "fluorogenic 2D6 probes exhibited poor signal-to-noise ratios" — a real, assay-level reason (not just a chemistry/modeling one) that CYP2D6 is the harder isoform for every team on the leaderboard, not just us.

**Base-rate-shift-robust thresholding** (`cypmode.challenge.threshold_tuning.find_robust_threshold` / `cross_validate_with_robust_threshold_tuning`). A single MCC-optimal threshold implicitly assumes the test base rate matches training's; a real base-rate mismatch can silently cost MCC — a known general risk for any threshold picked by optimizing on one label distribution and applying it to another. Implemented as a minimax choice over an assumed base-rate grid (0.05–0.50), validated with a real base-rate-shift stress test (resampling real validation-fold labels/probabilities to different rates, not simulated). **Real, honest result: the effect is real but asymmetric, not a clean win.** At the natural (unshifted) rate, robust ≈ naive (CYP3A4 0.372 vs 0.375, CYP2D6 0.080 vs 0.078 — negligible either way). Under a shift toward a *rarer* positive class than training (π below ~0.20), the robust threshold clearly helps (e.g. CYP3A4 at π=0.05: 0.232 vs 0.199 naive). Under a shift toward a *more common* positive class (π above ~0.30), it clearly hurts, sometimes substantially (CYP3A4 at π=0.45: 0.415 robust vs 0.481 naive) — the minimax criterion buys protection in one direction at real cost in the other. A "mean" criterion (average MCC across the same grid, instead of worst-case) was also tested and turned out to pick the *exact same threshold* as the naive MCC-optimal one in both isoforms — a wash, not an improvement. **Decision: not adopted as the default threshold** — we have no real evidence the blind test's TDI base rate skews lower than training's (if anything, the split-validity diagnostic above points the other way), so the minimax threshold's asymmetric cost isn't clearly justified. Kept as real, tested, documented infrastructure, usable if external evidence about the blind test's base rate ever surfaces.

**KNN-label (read-across) features** (`cypmode.challenge.knn_features`). For each compound, the known TDI status of its K nearest chemical neighbors (Tanimoto similarity on ECFP4), aggregated into 4 features (fraction positive, similarity-weighted fraction positive, mean similarity to those neighbors, neighbor count) and added to M3. Built fold-internally, not precomputed globally: a training compound's neighbor pool excludes itself (leave-one-out) and is restricted to the rest of that fold's training portion, and a validation compound's neighbor pool is the full training portion only — never the compound itself, never anything from its own validation fold — see the module docstring's leakage-guard tests for why a global precompute would leak. **Real result, same 5-fold CV protocol as M3: CYP3A4 MCC 0.300→0.312, CYP2D6 MCC 0.043→0.075 (+74% relative).** A genuine, positive result on both isoforms, largest relative gain on CYP2D6 — our real bottleneck. Candidate for folding into the assembled feature set alongside M3.

**Auxiliary direct-CYP-activity features, external data** (`cypmode.challenge.pubchem_auxiliary`, `cypmode.challenge.bindingdb_auxiliary`). One LightGBM classifier per isoform, trained on a broader, external compound population and applied to this project's own TDI compounds as an extra feature — no fold-internal OOF treatment needed (both sources are fully external to this project's own TDI-labeled data; see each module's own docstring for the reasoning, which differs from why the OOF Direct-Inhibition Bridge above needs OOF construction).

- **PubChem AID 1851** (NCATS qHTS cytochrome panel, 16,560 real compounds after excluding overlap with our own data). **Real, corrected result: CYP3A4 MCC 0.300→0.308, CYP2D6 MCC 0.043→0.071 (+64% relative).** A first version of this result showed CYP2D6 *dropping* to 0.020 — traced to a real data-handling bug, not a real finding: the raw PubChem file has replicate measurement rows per (compound, isozyme) pair (up to 7 for one pair), and merging without collapsing them first multiplied 16,560 real compounds into 86,721 rows, silently over-weighting whichever compounds happened to have replicates. Fixed with `drop_duplicates` before merging, not after; the corrected number is a genuine, positive result on both isoforms, not the apparent regression the bug produced. Kept in the record as a reminder that a surprising ablation result needs its data pipeline checked before it's trusted, the same discipline already applied to every leakage guard in this project.
- **BindingDB** (literature-curated Ki/IC50/EC50, targeted `getLigandsByUniprots` pulls for CYP3A4/P08684 and CYP2D6/P10635 specifically — confirmed ~3MB/~2MB each, not BindingDB's own 240MB–3GB full dumps). Combined via median affinity across repeated measurements for the same compound (a real quirk here too, but a different one from AID 1851's: independent measurements from different papers, not same-assay replicate rows, so median-combining rather than deduplicating is the right call). **Real result: CYP3A4 MCC 0.300→0.309, CYP2D6 MCC 0.043→0.089 (+107% relative) — the single largest individual CYP2D6 gain found so far**, ahead of KNN-label features (+74%) and AID 1851 (+64%). A real crash was hit and fixed along the way: a small fraction of BindingDB's own SMILES strings (7 of 8,679 for CYP3A4) carry a ChemAxon extended-annotation suffix plain RDKit can't parse — dropped, not passed through, after confirming they're a real but small fraction of the data (<0.1%).

All three auxiliary/read-across additions (KNN, AID 1851, BindingDB) were first tested as independent, separate additions to plain M3 at the naive 0.5 threshold, then genuinely combined and statistically tested (see next section) — not left as isolated ablations, per this project's own standing rule that a feature must be validated alone *and* wired into the assembled model.

**Combined-feature stacking, and the statistical-significance correction that followed** (`cypmode.challenge.combined_features`, `cypmode.challenge.stacking_significance`). First real attempt at stacking KNN + AID 1851 + BindingDB together for CYP2D6 on a single 5-fold split gave a startling result: MCC 0.059, *worse* than any individual addition (0.071–0.089) — a real, surprising finding, investigated rather than either dismissed or trusted at face value. Dropping AID 1851 (the most redundant of the three, 0.49-correlated with BindingDB) and testing KNN+BindingDB alone on the same single split still showed the same pattern (0.054). **The correction, motivated directly by a real methodology from Pat Walters' model-validation-central (patwalters.github.io/model-validation-central — "pooling more methods turns outright wins into ties" without proper correction): repeated the whole comparison over 5×5=25 real folds and applied Tukey HSD.** Result: **every pairwise comparison among M3, M3+BindingDB, M3+KNN, and M3+KNN+BindingDB came back non-significant (all p-adj ≥ 0.52, all confidence intervals crossing zero)** — the fold-to-fold noise (std ≈ 0.06–0.07) is large relative to the differences between means (≈ 0.01–0.02) at CYP2D6's real sample size. **The original "combining hurts" finding was single-split noise, not a genuine negative interaction** — a real, important correction, not a footnote: a surprising ablation result needs to survive repeated, corrected testing before being trusted, the same discipline already applied to the AID 1851 data-bug discovery above. Practical choice going forward: M3+KNN, since it has the best point estimate (mean MCC 0.092) and is the simplest of the tied options (one feature source, no external-API dependency at inference time) — not because it's been shown statistically superior, since it hasn't. This mirrors, at a much smaller scale, exactly what the challenge organizers themselves reported for the real interim TDI leaderboard: 26 teams statistically tied in "Tier 1" via the same kind of corrected significance test (Benjamini-Hochberg), spanning a real MCC range of 0.341–0.398.

**The same 25-fold rigor was then applied to CYP3A4**, whose only real result until now was a single-split combined-feature number (0.300→0.321) that looked genuinely positive and had not yet been checked for noise. It doesn't survive the check either: M3=0.309±0.055, M3+BindingDB=0.313±0.055, M3+KNN=0.321±0.052, M3+KNN+BindingDB=0.324±0.045 — every pairwise comparison again comes back non-significant (all p-adj ≥ 0.74). The single-split 0.321 was, like CYP2D6's case, within fold-to-fold noise, not a proven real effect. Practical choice for CYP3A4 is the same kind of non-claim as CYP2D6's: M3+KNN or M3+KNN+BindingDB are reasonable defaults on point estimate, not because either is statistically superior to plain M3.

**Structure standardization for cross-dataset matching** (`cypmode.challenge.structure_standardization`, via `chembl_structure_pipeline` — a real, rdkit-only-dependency package). Both auxiliary modules' exact-overlap leakage checks were matching on plain canonical SMILES, which treats a salt form as a different compound from its free base (confirmed directly: ketoconazole vs. ketoconazole.Cl canonicalize to two different strings) — a real gap that could silently miss a genuine duplicate between an external dataset and this project's own compounds. Both now match on the standardized parent structure instead.

**Quantum-derived electronic-structure features** (`cypmode.challenge.quantum_pharmacophore`, via tblite's GFN2-xTB — see the module's own docstring for why tblite over xtb-python, and semi-empirical over full DFT: confirmed directly this session that even the crudest possible DFT-adjacent level, HF/STO-3G via pyscf, takes ~65 seconds on a 71-atom drug molecule vs. tblite's ~1 second, a ~65x slowdown that would put the full training set at ~111 hours single-threaded even at that minimal level — pyscf itself is real and well-maintained, just the wrong tool for a several-thousand-compound batch). Feature vector: HOMO/LUMO energies and gap, dipole magnitude, total energy, and partial-charge summary stats. Single-split result was mixed/negative for both isoforms (CYP3A4 0.312→0.308, CYP2D6 0.043→0.028) — per this project's own standing rule, checked with the same repeated 5×5 CV + Tukey HSD rigor rather than accepted at face value. **The negative reading doesn't survive the check either**: for both isoforms, every pairwise comparison among M3, M3+KNN, M3+Quantum, and M3+KNN+Quantum comes back non-significant (CYP3A4 all p-adj ≥ 0.85; CYP2D6 all p-adj ≥ 0.16). The quantum feature is statistically indistinguishable from plain M3 in either direction — not proven harmful, not proven helpful. Consistent with every other single-split "interesting" result checked this session (KNN+BindingDB for both isoforms): a single 5-fold split is not enough to trust, whichever direction it points.

**3-point pharmacophore fingerprints** (`cypmode.challenge.pharmacophore_fingerprint`, via pmapper — real, actively maintained, lightweight rdkit+networkx dependency, no compiled numerical backend and so no OpenMP-conflict risk with LightGBM the way tblite has). Encodes the 3D spatial arrangement of pharmacophoric features (H-bond donors/acceptors, aromatic rings, hydrophobic regions, ionizable groups) relative to each other, as a 2048-bit fingerprint — a real, distinct feature family from both the 2D Morgan fingerprint already in M3 and the 0D scalar quantum-electronic features above, since neither captures 3D spatial feature arrangement. Confirmed ~350 ms/compound (~36 min single-threaded for the full training set). Went straight to the real 25-fold repeated-CV + Tukey HSD check (not a single split first) per the lesson learned from the quantum feature above. **Same honest result as quantum**: no pairwise comparison is significant for either isoform (CYP3A4 all p-adj ≥ 0.56; CYP2D6 all p-adj ≥ 0.15), and the point estimate actually leans slightly *negative* for both (CYP3A4 M3+Pharmacophore=0.303 vs. M3=0.309; CYP2D6 0.053 vs. 0.067) — not a significant harm either, but no evidence of benefit.

**A real, honest pattern across three independent feature additions now** (KNN+BindingDB, quantum-electronic, pharmacophore-fingerprint): none moves M3's MCC by a statistically defensible amount, for either isoform, despite each being a real, mechanistically-motivated feature. Taken together with three *external* signals pointing the same direction — the OpenADMET-ExpansionRx retrospective's own finding that classical ML (LightGBM/XGBoost/CatBoost) ranked no higher than #46 among top ADMET-challenge submissions, and two published CYP-specific papers (idrugLab's FP-GNN, Seomun & Yoo's MTMM-CYP) both built around fusing multiple *learned* representations (fingerprint+GNN, or graph+conv+transformer) rather than classical descriptors alone — this is a real, converging case that the ceiling here may be M3's classical-descriptor-plus-LightGBM architecture itself, not a missing hand-crafted feature. Motivates the ChemBERTa work below: a genuinely different (learned, pretrained, transformer-based) representation, not another hand-engineered one.

**Transformer-based SMILES embeddings** (`cypmode.challenge.chemberta_features`, via ChemBERTa — `seyonec/ChemBERTa-zinc-base-v1`, a real, published RoBERTa model pretrained on ~77M ZINC SMILES strings). A third molecular representation alongside M3's existing two, following MTMM-CYP's own real methodological idea (multiple representations, shared across isoforms) without adopting MTMM-CYP's own code (Python 3.7/TensorFlow-1.x-pinned, no license — see the decision log). Confirmed directly: 768-dim mean-pooled embedding, ~35 ms/molecule on CPU (~3.6 min for the full training set), no 3D conformer step needed at all (operates on tokenized SMILES directly), so essentially no embedding-failure mode the way the quantum and pharmacophore features have. **Real architectural constraint, confirmed freshly this session**: `import torch` followed by fitting an `LGBMClassifier` in the same process segfaults (exit code 139) — the same OpenMP conflict already documented for `cypmode.challenge.multitask`, now confirmed to extend to this module too. `chemberta_features.py`'s own `_main()` therefore only extracts and caches embeddings; evaluating them against M3 happens in a fully separate process (`cypmode.challenge.chemberta_significance`, LightGBM-only, never imports torch), the same isolation discipline `tests/test_multitask.py` already requires.

**Real, statistically significant result — and unlike every feature above, this one didn't come back a null result.** Adding raw ChemBERTa embeddings directly to M3's feature vector *significantly hurts* CYP3A4: M3=0.309 → M3+ChemBERTa=0.255 (meandiff=-0.0545, p-adj=0.0002, reject=True), and M3+KNN=0.321 → M3+KNN+ChemBERTa=0.256 (meandiff=-0.0644, p-adj<0.0001, reject=True) — KNN's own real (if individually non-significant) benefit is wiped out once ChemBERTa joins the feature vector. CYP2D6 shows the identical direction at a smaller, not-quite-significant magnitude for the M3 comparison (p=0.118) but a significant loss once KNN is involved (M3+KNN=0.092 → M3+KNN+ChemBERTa=0.038, p=0.0096).

**Real interpretation, not just "ChemBERTa doesn't help": this is very likely a data-representation mismatch, not evidence against transformer embeddings generally.** Concatenating a dense, highly-correlated 768-dimensional embedding onto M3's already-large feature vector, then handing the result to a tree-based gradient-boosting model trained on only ~3,500–4,800 examples, is a real recipe for the model spending its limited splits on noisy embedding dimensions instead of the cleaner signal already in the fingerprint/descriptors — LightGBM has no learned projection step to compress or denoise a dense embedding the way a neural fusion layer would. This is consistent with, not contradicting, the MTMM-CYP/FP-GNN/ExpansionRx pattern noted above: those approaches don't bolt a transformer embedding onto a tree model's raw feature matrix either — they route each representation through its own learned branch before fusion.

**So that proper architecture was built and tested** (`MultiBranchSharedTrunkModel` in `cypmode.challenge.multitask`: M3 and the ChemBERTa embedding each get their own branch — Linear→ReLU→Dropout — before concatenation into the shared trunk, rather than one raw block). **It doesn't help either — if anything, it's slightly worse than the M3-only shared trunk on the same single 5-fold split**: CYP3A4 shared-trunk-M3-only=0.250 (untuned) / 0.266 (threshold-tuned) vs. shared-trunk-M3+ChemBERTa-fusion=0.237; CYP2D6 0.111 / 0.113 vs. 0.088. Two independent, honest attempts at using ChemBERTa now point the same direction: naive LightGBM concatenation significantly *hurts*, and a proper neural fusion architecture shows no benefit either (not yet checked at 25-fold rigor, but the point estimate moved the wrong way both times). **Real, honest conclusion for this dataset at this size (~4,800 compounds, ~6,100 max)**: a pretrained general-purpose SMILES transformer embedding doesn't appear to add real signal beyond M3's existing descriptor+fingerprint representation for CYP TDI classification specifically — a genuinely different outcome from ADMET regression tasks at larger scale (ExpansionRx: ~7,600 compounds, continuous multi-endpoint) where GNN/foundation-model approaches did win. Worth remembering as a real, task-specific finding, not a blanket claim about transformer embeddings.

Separately, worth noting honestly: even without ChemBERTa, the M3-only shared-trunk neural model (0.25–0.27 for CYP3A4) doesn't beat the classical LightGBM M3 baseline (~0.31) on this same task — the shared-trunk hypothesis itself remains unproven, independent of the ChemBERTa question.
